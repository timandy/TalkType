# 窗口与终端锁定：原理与支持范围

本文说明 clawbot-ilink-relay 如何把消息投递到目标位置，支持哪些窗口，以及每一类的实现原理和已验证情况。

## 1. 整体结构

```
消息来源（relay.Source）                投递（relay.Deliverer）                 目标
┌──────────────────────┐   Message   ┌─────────────────────────┐
│ 微信 ilink.Client      │ ──────────► │ winlock.Manager.Inject  │ ──► 当前光标（未锁定）
│ 控制台 console.Source  │             │  按锁定状态选择发送方式  │ ──► 后台写入终端（锁定终端）
└──────────────────────┘             └─────────────────────────┘ ──► 切前台输入（锁定其他窗口）
```

- **消息来源**只负责拿到消息和自己的确认语义。微信来源负责去重、ACK、游标、白名单、回执；控制台来源逐行读取标准输入。
  用 `-source wechat|console` 选择。
- **投递**统一由 `relay.Deliverer` 完成：串行投递，避免多条消息文字交错。锁定的目标已关闭时弹通知，并返回
  `relay.ErrDiscarded`，来源据此丢弃该消息（微信来源会 ACK 并推进游标，不会无限重试）。

## 2. 快捷键

| 操作 | 效果 |
|---|---|
| 未锁定时按 Alt+/ | 锁定当前窗口或终端 |
| 已锁定，在**别的**窗口或终端标签里按 Alt+/ | 锁定切换到当前这个，通知显示“已切换到…” |
| 已锁定，在**锁定的那个**里按 Alt+/ | 解除锁定，恢复为输入到当前光标 |
| 350 毫秒内连按两下 Alt+/ | 无论在哪里，直接解除锁定 |
| 在目标终端里运行 `clawbot-ilink-relay.exe -lock` | 精确锁定这个终端 |
| 运行 `clawbot-ilink-relay.exe -unlock` | 解除锁定 |

“是不是同一个目标”的判断：终端按 shell 进程 PID + 创建时间比较；窗口按窗口句柄比较；
锁定的是终端、但这次分不清是哪个标签时，按所在窗口比较。

## 3. 支持范围

| 类别 | 例子 | 发送方式 | 多标签时如何确定目标 | 验证情况 |
|---|---|---|---|---|
| 传统控制台窗口 | 独立的 PowerShell、cmd 窗口（conhost） | 后台写入 | 一个窗口只有一个控制台 | 已实测：最小化、无焦点时写入成功，前台窗口不变 |
| Windows Terminal | 多标签的 PowerShell、cmd | 后台写入 | 标题探测（见 5.3） | 已实测：两个标签时识别出当前标签并写入成功；用户实测切换标签后锁定正确 |
| JetBrains IDE 终端 | IntelliJ IDEA、GoLand 等；Reworked 2025 和 Classic 引擎 | 后台写入 | 尺寸探测（见 5.4），失败时用最近输入（见 5.5） | 已实测：后台写入 IDEA 终端成功；GoLand 的 Window 模式、窗口最大化、6 个终端时识别出当前显示的终端（0.19 秒） |
| VS Code 终端 | 集成终端 | 后台写入 | 同 JetBrains | 未实测，机制相同 |
| 其他所有窗口 | Chrome、Edge、IDE 编辑器和其他面板、记事本、聊天软件等 | 切前台输入 | 不适用 | 已实现，用户接受这种方式 |
| 不允许锁定 | 桌面、任务栏、本程序自己的窗口和所在终端 | — | — | 会弹通知说明原因 |

识别为“终端”的 shell 进程：`powershell.exe`、`pwsh.exe`、`cmd.exe`、`bash.exe`、`wsl.exe`、`nu.exe`。

## 4. 三种发送方式

### 4.1 输入到当前光标（未锁定）

用 `SendInput` 注入 `KEYEVENTF_UNICODE` 键盘事件：文本按 UTF-16 码元拆成按下/抬起事件，换行和制表符转成
`VK_RETURN`、`VK_TAB`，每 512 个事件一批。不使用剪贴板和输入法，中文、Emoji 可直接输入。
键盘事件只会进入**当前前台窗口**的焦点控件。

### 4.2 后台写入终端（锁定终端）

用 `AttachConsole(pid)` 挂到目标 shell 所在的控制台，打开 `CONIN$`，用 `WriteConsoleInputW` 把按键记录
（`KEY_EVENT` 类型的 `INPUT_RECORD`）直接写进该控制台的**输入缓冲区**。shell 读到的就像用户亲手敲的键：

- 不需要窗口焦点：窗口在后台、最小化，或者是后台标签都能收到；
- 不切换窗口，不闪烁，也不打断用户正在别处打字；
- 对传统控制台和 ConPTY 伪控制台都有效。Windows Terminal、JetBrains、VS Code 的终端底层都是 ConPTY，
  每个标签对应一个独立的宿主进程（`OpenConsole.exe` 或 `conhost.exe`）。

一个进程同一时间只能挂在一个控制台上，而本程序自己的控制台要用来打印日志，所以挂接和写入由**辅助子进程**完成：
同一个 exe 以 `--clawbot-console-helper` 为第一个参数、`DETACHED_PROCESS` 方式启动，通过 stdin/stdout 交换 JSON，
写完即退出。辅助子进程还负责查询控制台信息（窗口句柄、标题、光标所在行）和标题探测。

### 4.3 切前台输入（锁定其他窗口）

发送时：

1. 记下当前前台窗口；目标最小化的先还原；
2. 用 `AttachThreadInput` 临时关联到当前前台线程的输入队列，再 `BringWindowToTop` + `SetForegroundWindow`，
   绕过系统对跨进程抢前台的限制；
3. 按 4.1 的方式输入；
4. 恢复原来的前台窗口，原本最小化的目标重新最小化。

发送瞬间会有一次窗口切换，约 0.3～0.5 秒。

## 5. 按下 Alt+/ 时如何确定目标

### 5.1 热键与单击/连按

- 用 `RegisterHotKey(MOD_ALT | MOD_NOREPEAT, VK_OEM_2)` 注册全局热键。`VK_OEM_2` 是美式布局上 `/ ?` 所在的物理键；
- 热键、托盘图标、通知都由一个隐藏的消息窗口（`HWND_MESSAGE`）在独立线程上处理；
- 第一次按下时记住当时的前台窗口，并启动 350 毫秒定时器。期间再按一次算连按（解除锁定）；
  定时器到期则按单击处理。所以单击会有约 0.35 秒延迟。

### 5.2 判断前台窗口里有没有终端

1. 枚举系统中所有 shell 进程，交给辅助子进程逐个挂接，查询其控制台的 `GetConsoleWindow()` 及其顶层所有者
   （`GetAncestor(GA_ROOTOWNER)`）；
2. **直接匹配**：控制台窗口就是前台窗口（传统控制台），或者伪控制台窗口的所有者是前台窗口
   （Windows Terminal 会把伪控制台窗口的所有者设为自己的窗口）；
3. **进程树匹配**：没有直接匹配时，取前台窗口所属进程的子孙 shell（JetBrains、VS Code 的伪控制台窗口没有所有者，
   但 shell 是 IDE 进程启动的）；
4. 同一个控制台里的多个 shell（例如 PowerShell 里又开了 cmd）只算一个，取最外层的；
5. 排除本程序自己所在的控制台。若当前选中的正是它，则拒绝锁定，否则消息会输回本程序。

只有一个候选时直接锁定；有多个候选（多个标签）时，依次尝试 5.3～5.5；都确定不了时按普通窗口处理（切前台）。

### 5.3 标题探测（Windows Terminal）

Windows Terminal 的窗口标题跟随当前标签的控制台标题。依次把每个候选控制台的标题临时改成随机标记
（`SetConsoleTitleW`），轮询窗口标题是否跟着变，变了的就是当前标签，随后立即恢复原标题。
只对“直接匹配”的候选使用。JetBrains 的窗口标题与终端标签无关，这一步对它无效（已实测）。

### 5.4 尺寸探测（JetBrains / VS Code）

IDE 只会调整**正在显示**的终端的尺寸，尺寸变化会通过 ConPTY 的信号通道传给该终端的宿主进程，后台标签不受影响。

1. 用 `NtQueryInformationProcess(ProcessConsoleHostProcess)` 找到每个候选 shell 的控制台宿主进程；
2. 用 `GetProcessIoCounters` 记下每个宿主的读操作计数；
3. 把前台窗口宽高各缩小 24 像素（`SetWindowPos`，不激活、不移动），最多等 500 毫秒；
4. 读计数变化的宿主就是当前显示的终端；随后恢复窗口原尺寸。

只有恰好一个宿主有反应时才采用结果。窗口最小化时跳过。代价是窗口边缘会轻微闪一下，实测约 0.2 秒。
已在最大化的窗口上实测，缩小和恢复都正常。

### 5.5 最近输入（兜底）

程序常驻一个采样器：每 2 秒收集一次所有 shell 的宿主进程，每 200 毫秒读取它们的读操作计数。
用户在某个终端里按键，IDE 就把按键写进该终端宿主的输入管道，宿主每读一次计数就加一；后台标签的计数不变。
尺寸探测得不到唯一结果时，选最近一次计数有变化的终端。

已实测：10 个终端空闲 15 秒，读计数都没有变化；切换窗口焦点不会使读计数变化。
所以这一步只反映键盘输入：用鼠标切到新标签、但还没在里面按过键时，会选中上一个打过字的标签。

### 5.6 -lock 命令

在目标终端里运行 `clawbot-ilink-relay.exe -lock`。它用 `FindWindowExW(HWND_MESSAGE, …)` 找到正在运行的实例的
隐藏窗口，通过 `WM_COPYDATA` 发送自己父进程（运行这条命令的 shell）的 PID，由正在运行的实例锁定该 shell 所在的控制台。
这条路径不需要任何探测，可精确指定标签。

## 6. 目标关闭检测

- 锁定终端时记下 shell 的 PID 和进程创建时间。发送前用 `GetExitCodeProcess` 和 `GetProcessTimes` 确认进程仍在运行，
  且不是复用了同一 PID 的新进程；
- 锁定窗口时发送前用 `IsWindow` 检查窗口句柄；
- 目标已关闭：不发送，弹出“消息没有发送”通知，该消息被丢弃。锁定状态保留，直到用户按 Alt+/ 解除或切换。

## 7. 通知

用 `Shell_NotifyIconW` 在托盘区放一个图标，通过气泡提示（`NIF_INFO`）显示状态变化。文案示例：

- 锁定终端：“已锁定当前终端：消息会在后台发送到「GoLand · PS E:\work>」，不会切换窗口。”
  终端名优先显示光标所在行（通常是带目录的提示符），方便认出是哪个标签；
- 锁定窗口：“已锁定当前窗口：消息只会发送到「…」，发送时会短暂切换到该窗口。”
- 切换：“已切换到当前终端/窗口：…”
- 解除：“已解除锁定：已恢复为输入到当前光标位置。”
- 目标关闭：“消息没有发送：锁定的窗口或终端已经关闭。”

## 8. 已知限制

- **IDE 主窗口里没有显示终端时**：在编辑器等区域按 Alt+/，尺寸探测没有反应，会退回到“最近输入”，
  锁到某个打过字的终端，而不是锁定窗口本身。改进方向：尺寸探测明确没有终端在显示时，直接按普通窗口处理。
- **同一个 IDE 进程有多个项目窗口**：进程树匹配会包含所有窗口的终端；尺寸探测只影响当前窗口，不受此影响，
  但兜底的“最近输入”可能选中其他窗口的终端。
- **管理员终端**：以管理员身份运行的终端无法后台写入（`AttachConsole` 被拒），除非本程序也以管理员身份运行。
  切前台方式同样受 UIPI 限制。
- **键盘布局**：热键绑定的是 `VK_OEM_2` 物理键，换成非美式布局时可能不是 `/` 键。
- **热键冲突**：Alt+/ 被其他程序占用时，锁定功能不可用，启动时打印警告，消息始终输入到当前光标。
- **终端里正在运行其他程序**：后台写入的内容会进入那个程序（例如 python、vim），与亲手打字效果相同。
- **Windows Terminal 关闭了应用标题**（`suppressApplicationTitle`）：标题探测无效，会退回到尺寸探测和最近输入。
