# 窗口与终端锁定：原理与支持范围

本文说明 WeType 如何把消息投递到目标位置，支持哪些窗口，以及每一类的实现原理和已验证情况。

## 1. 整体结构

```
消息来源（relay.Source）                投递（relay.Deliverer）                 目标
┌──────────────────────┐   Message   ┌─────────────────────────┐
│ 微信 ilink.Client      │ ──────────► │ winlock.Manager.Inject  │ ──► 当前光标（未锁定）
│ 控制台 console.Source  │             │  按锁定状态选择发送方式  │ ──► 后台写入终端（锁定终端）
└──────────────────────┘             └─────────────────────────┘ ──► 切前台输入（锁定其他窗口）
```

- **消息来源**只负责拿到消息和自己的确认语义。微信来源负责去重、ACK、游标、白名单、回执；控制台来源逐行读取标准输入。
  用 `-source wechat|console` 选择。
- **投递**统一由 `relay.Deliverer` 完成：串行投递，避免多条消息文字交错。锁定的目标已关闭时弹通知，并返回
  `relay.ErrDiscarded`，来源据此丢弃该消息（微信来源会 ACK 并推进游标，不会无限重试）。

## 2. 快捷键

| 操作 | 效果 |
|---|---|
| 未锁定时按 Alt+. | 锁定当前窗口或终端 |
| 已锁定，在**别的**窗口或终端标签里按 Alt+. | 锁定切换到当前这个，通知显示“已切换至…” |
| 已锁定，在**锁定的那个**里按 Alt+. | 解除锁定，恢复为输入到当前光标 |
| 在任意位置按 Alt+/ | 直接解除锁定 |
| 在目标终端里运行 `wetype.exe -lock` | 精确锁定这个终端 |
| 运行 `wetype.exe -unlock` | 解除锁定 |

“是不是同一个目标”的判断：终端按 shell 进程 PID + 创建时间比较；窗口按窗口句柄比较；
锁定的是终端、但这次分不清是哪个标签时，按所在窗口比较。

## 3. 支持范围

| 类别 | 例子 | 发送方式 | 多标签时如何确定目标 | 验证情况 |
|---|---|---|---|---|
| 传统控制台窗口 | 独立的 PowerShell、cmd 窗口（conhost） | 后台写入 | 一个窗口只有一个控制台 | 已实测：最小化、无焦点时写入成功，前台窗口不变 |
| Windows Terminal | 多标签的 PowerShell、cmd | 后台写入 | 标题探测（见 5.3） | 已实测：两个标签时识别出当前标签并写入成功；用户实测切换标签后锁定正确 |
| JetBrains IDE 终端（正在显示） | IntelliJ IDEA、GoLand 等；Reworked 2025 和 Classic 引擎 | 后台写入 | 尺寸探测（见 5.4） | 已实测：后台写入 IDEA 终端成功；GoLand 的 Window 模式、窗口最大化、6 个终端时识别出正在显示的终端（约 0.1 秒） |
| VS Code 终端（正在显示） | 集成终端 | 后台写入 | 同 JetBrains | 未实测，机制相同 |
| IDE 的其他部分 | 代码编辑器、终端被隐藏的 IDE 窗口、AI 聊天框等面板 | 切前台输入 | 尺寸探测确认没有终端在显示 | 已实测：两个 GoLand 编辑器窗口都正确判为普通窗口 |
| 其他所有窗口 | Chrome、Edge、记事本、聊天软件等 | 切前台输入 | 不适用 | 已实现，用户接受这种方式 |
| 不允许锁定 | 桌面、任务栏、本程序自己的窗口和所在终端 | — | — | 会弹通知说明原因 |

识别为“终端”的 shell 进程：`powershell.exe`、`pwsh.exe`、`cmd.exe`、`bash.exe`、`wsl.exe`、`nu.exe`。

总的原则：**只有确认目标是一个正在显示的终端，才后台写入；凡是探测不到终端的，一律按普通窗口处理，发送时切前台**，和浏览器一样。

## 4. 三种发送方式

### 4.1 输入到当前光标（未锁定）

用 `SendInput` 注入 `KEYEVENTF_UNICODE` 键盘事件：文本按 UTF-16 码元拆成按下/抬起事件，换行和制表符转成
`VK_RETURN`、`VK_TAB`，每 512 个事件一批。不使用剪贴板和输入法，中文、Emoji 可直接输入。
键盘事件只会进入**当前前台窗口**的焦点控件。

### 4.2 后台写入终端（锁定终端）

用 `AttachConsole(pid)` 挂到目标 shell 所在的控制台，打开 `CONIN$`，用 `WriteConsoleInputW` 把按键记录
（`KEY_EVENT` 类型的 `INPUT_RECORD`）直接写进该控制台的**输入缓冲区**。shell 读到的就像用户亲手敲的键：

- 不需要窗口焦点：窗口在后台、最小化，或者是后台标签都能收到；
- 不切换窗口，不闪烁，也不打断用户正在别处打字；
- 对传统控制台和 ConPTY 伪控制台都有效。Windows Terminal、JetBrains、VS Code 的终端底层都是 ConPTY，
  每个标签对应一个独立的宿主进程（`OpenConsole.exe` 或 `conhost.exe`）。

一个进程同一时间只能挂在一个控制台上，而本程序自己的控制台要用来打印日志，所以挂接和写入由**辅助进程**完成：
同一个 exe 以 `--wetype-console-helper serve` 参数、`DETACHED_PROCESS` 方式启动，通过 stdin/stdout 逐行交换 JSON。
辅助进程在第一次使用时启动，之后**常驻复用**，省去每次启动进程的约 45 毫秒；本程序退出时它的 stdin 被关闭，随之退出。
请求还没送达时辅助进程已退出，会自动重启并重发；请求已送达但中途出错则不重发，避免重复输入。
挂接期间目标控制台里的 Ctrl+C、关闭等事件也会通知到辅助进程，它会忽略这些事件，不会因此退出。
辅助进程还负责查询控制台信息（窗口句柄、标题、光标所在行）和标题探测。

### 4.3 切前台输入（锁定其他窗口）

发送时：

1. 记下当前前台窗口；目标最小化的先还原；
2. 用 `AttachThreadInput` 临时关联到当前前台线程的输入队列，再 `BringWindowToTop` + `SetForegroundWindow`，
   绕过系统对跨进程抢前台的限制；
3. 按 4.1 的方式输入；
4. 恢复原来的前台窗口，原本最小化的目标重新最小化。

发送瞬间会有一次窗口切换，约 0.3～0.5 秒。

## 5. 按下 Alt+. 时如何确定目标

### 5.1 热键

- 用 `RegisterHotKey` 注册两个全局热键，修饰键为 `MOD_ALT | MOD_NOREPEAT`。`MOD_ALT` 不区分左右，左右两个 Alt 键都能触发：
  - **Alt+.**（`VK_OEM_PERIOD`）：锁定当前目标；已锁定时，当前目标就是锁定的那个则解除，否则切换过去；
  - **Alt+/**（`VK_OEM_2`，美式布局上 `/ ?` 所在的物理键）：在任意位置直接解除锁定。
- 锁定和解除分成两个快捷键，每个快捷键的含义都是确定的，不需要等待判断是否连按，按下立即生效；
- 热键和提示卡片由一个隐藏的消息窗口（`HWND_MESSAGE`）在 UI 线程上处理。UI 线程收到 Alt+. 只记下当时的前台窗口，
  交给**工作协程**去识别目标，自己立刻返回，所以识别过程不会卡住卡片动画。

### 5.2 判断前台窗口里有没有终端

1. 枚举 shell 进程，交给辅助进程逐个挂接，查询其控制台的 `GetConsoleWindow()` 及其顶层所有者
   （`GetAncestor(GA_ROOTOWNER)`）。前台窗口本身是终端（`ConsoleWindowClass`、`CASCADIA_HOSTING_WINDOW_CLASS`）时
   查询全部 shell；其他窗口只查询它自己的子孙 shell，没有就直接按普通窗口处理（例如浏览器，实测 14 毫秒）；
2. **直接匹配**：控制台窗口就是前台窗口（传统控制台），或者伪控制台窗口的所有者是前台窗口
   （Windows Terminal 会把伪控制台窗口的所有者设为自己的窗口）；
3. **进程树匹配**：没有直接匹配时，取前台窗口所属进程的子孙 shell（JetBrains、VS Code 的伪控制台窗口没有所有者，
   但 shell 是 IDE 进程启动的）；
4. 同一个控制台里的多个 shell（例如 PowerShell 里又开了 cmd）只算一个，取最外层的；
5. 排除本程序自己所在的控制台。若当前选中的正是它，则拒绝锁定，否则消息会输回本程序。

之后按匹配方式分两种：

- **直接匹配**（窗口本身就是终端）：只有一个控制台就直接锁定；有多个（多个标签）时用 5.3 的标题探测，失败再用 5.4 的尺寸探测；
- **进程树匹配**（IDE）：IDE 进程下有终端，不代表它显示在当前窗口里，比如终端面板被隐藏、或在另一个窗口里。
  所以**即使只有一个候选也要做 5.4 的尺寸探测**，确认它正在显示。

尺寸探测的结果：恰好一个终端有反应就后台写入；没有终端有反应（例如在代码编辑器里按 Alt+.，终端没显示）
就按普通窗口处理；多个终端同时有反应（例如分屏显示两个终端）也按普通窗口处理，通知里提示可用 `-lock` 指定。

### 5.3 标题探测（Windows Terminal）

Windows Terminal 的窗口标题跟随当前标签的控制台标题。**同时**把每个候选控制台的标题改成各不相同的随机标记
（`SetConsoleTitleW`），轮询窗口标题变成了哪一个，就是当前标签，随后恢复原标题。实测约 30 毫秒
（早先逐个尝试，每个不是当前标签的候选都要等满 600 毫秒，两个标签时要 0.75 秒）。
只对“直接匹配”的候选使用。JetBrains 的窗口标题与终端标签无关，这一步对它无效（已实测）。

### 5.4 尺寸探测（JetBrains / VS Code）

IDE 只会调整**正在显示**的终端的尺寸，尺寸变化会通过 ConPTY 的信号通道传给该终端的宿主进程，后台标签不受影响。

1. 用 `NtQueryInformationProcess(ProcessConsoleHostProcess)` 找到每个候选 shell 的控制台宿主进程；
2. 用 `GetProcessIoCounters` 记下每个宿主的读操作计数；
3. 把前台窗口的底边**逐级**上移（`SetWindowPos`，不激活、不移动），每 10 毫秒检查一次：

   | 级别 | 底边上移 | 本级最多等待 | 针对的情况 |
   |---|---|---|---|
   | 1 | 24 像素 | 60 毫秒 | 终端单独成窗口（Window / Float 模式），整个窗口都是终端 |
   | 2 | 64 像素 | 60 毫秒 | 终端停靠在 IDE 主窗口里，上移的高度只有一部分分给终端面板 |
   | 3 | 120 像素 | 100 毫秒 | 同上，终端面板占比更小 |

   像素数按窗口所在显示器的 DPI 换算（150% 缩放时第 1 级为 36 像素），最多上移窗口高度的一半。
   每一级都相对原始尺寸计算。**只改高度、不改宽度**：终端只少几行，列数不变，不会整屏重新折行，滚动位置也不会跳；
4. 读计数变化的宿主就是正在显示的终端；发现第一个反应后再等 30 毫秒，确认没有同时显示的其他终端，随后恢复窗口原尺寸。

实测终端单独成窗口时，第 1 级 10～20 毫秒就有反应，整个识别约 0.1 秒，窗口底部只闪 24 像素。
没有终端在显示时要等完三级（共 220 毫秒）才能下结论，整个识别约 0.26 秒，窗口底部最多闪 120 像素。
窗口最小化时无法探测，按普通窗口处理。
调整尺寸时线程临时切到按显示器 DPI 工作，读写的都是物理像素，恢复后尺寸与原来分毫不差（已在最大化的窗口上实测）。

### 5.5 -lock 命令

在目标终端里运行 `wetype.exe -lock`。它用 `FindWindowExW(HWND_MESSAGE, …)` 找到正在运行的实例的
隐藏窗口，通过 `WM_COPYDATA` 发送自己父进程（运行这条命令的 shell）的 PID，由正在运行的实例锁定该 shell 所在的控制台。
这条路径不需要任何探测，可精确指定标签。

## 6. 目标关闭检测

- 锁定终端时记下 shell 的 PID 和进程创建时间。发送前用 `GetExitCodeProcess` 和 `GetProcessTimes` 确认进程仍在运行，
  且不是复用了同一 PID 的新进程；
- 锁定窗口时发送前用 `IsWindow` 检查窗口句柄；
- 目标已关闭：不发送，弹出“消息没有发送”通知，该消息被丢弃。锁定状态保留，直到用户按 Alt+/ 解除，或按 Alt+. 切换。

## 7. 通知

状态变化在屏幕右下角弹出自绘的提示卡片。早先用的托盘气泡（`Shell_NotifyIconW`）会被系统转成 Windows 通知，
出现前有明显延迟，所以改为自己画。

### 7.1 外观

| 级别 | 颜色 | 图标 | 用于 |
|---|---|---|---|
| 成功 | 翠绿 → 青 渐变 | ✓ | 锁定、切换锁定目标 |
| 信息 | 蓝 → 靛 渐变 | ℹ | 解除锁定、当前没有锁定 |
| 警告 | 琥珀 → 橙 渐变 | ! | 窗口不能锁定、消息没有发送 |
| 错误 | 红 → 粉 渐变 | ✕ | 锁定失败 |

卡片宽 360 像素（按显示器 DPI 缩放），圆角、底部柔和阴影，左侧半透明圆形图标，右侧标题（16 像素粗体）加最多 4 行正文（14 像素），字体为微软雅黑 UI。

### 7.2 实现

- 每张卡片是一个分层窗口（`WS_EX_LAYERED`），样式为 `WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE | WS_EX_TRANSPARENT`：
  总在最前、不出现在任务栏、不抢焦点、鼠标可以穿透；
- 渲染到 32 位 DIB：先逐像素画渐变底色和图标底圆，再画文字，
  最后用圆角矩形的有符号距离函数逐像素计算透明度，得到抗锯齿圆角和阴影，并做 alpha 预乘；
- 文字用 4 倍超采样绘制：按 4 倍字号用 GDI `DrawTextW` 画到黑底蒙版上（标题和图标在红色通道、正文在绿色通道），
  再按 4×4 像素块取平均缩小回原尺寸，得到灰度抗锯齿的覆盖率，最后按覆盖率把白色叠到底色上。
  这样文字边缘平滑，且不依赖 ClearType 和系统字体平滑设置（ClearType 的彩色子像素在分层窗口上会产生锯齿和色边）；
  覆盖率做了轻微的 gamma 校正（指数 0.8），避免浅色文字叠在彩色底上时笔画显得偏细；
- 用 `UpdateLayeredWindow(ULW_ALPHA)` 显示，整体透明度通过 `BLENDFUNCTION.SourceConstantAlpha` 每帧调整，位图只渲染一次；
- UI 线程设为按显示器 DPI 工作（`SetThreadDpiAwarenessContext(PER_MONITOR_AWARE_V2)`），用 `GetDpiForMonitor` 取 DPI，高分屏下不会模糊；
- 卡片出现在前台窗口所在显示器的工作区右下角（不压任务栏）。

### 7.3 动画

由 UI 线程上约 15 毫秒一次的定时器驱动。所有卡片都静止（停留阶段）时，定时器放慢到下一张卡片开始淡出的时刻；
位置和透明度没有变化时不调用 `UpdateLayeredWindow`；没有卡片时定时器停止。

- **出现**：0.22 秒内从右侧滑入并淡入（缓出曲线）；
- **堆叠**：最新的在最下面，新卡片出现时把已有卡片往上顶，位置按指数平滑追随目标（时间常数 70 毫秒），看起来像冒泡；
- **透明度**：从新到旧依次为 100%、82%、64%、46%；
- **消失**：每张卡片停留 3.5 秒后在 0.6 秒内淡出；同时超过 4 张时，最旧的提前淡出。

动画参数和计算（透明度曲线、堆叠位置、平滑、圆角距离函数）在 `toast_layout.go` 中，与平台无关，有单元测试。

### 7.4 文案示例

文案风格：标题是简短的状态短语；正文按行组织，依次写明目标、发送方式和操作提示，不加句号。
文案中不出现程序名（exe 可能被改名），需要指代时用“本程序”。

| 场景 | 级别 | 标题 | 正文 |
|---|---|---|---|
| 锁定终端 | 成功 | 已锁定终端 | 目标：GoLand · PS E:\work><br>方式：后台发送，不切换窗口<br>按 Alt+/ 解除锁定 |
| 锁定窗口 | 成功 | 已锁定窗口 | 目标：Google Chrome<br>方式：切换至该窗口后发送<br>按 Alt+/ 解除锁定 |
| 切换目标 | 成功 | 已切换至终端 / 已切换至窗口 | 同上 |
| 窗口里有多个可见终端 | 成功 | 已锁定窗口 | 目标：…<br>方式：切换至该窗口后发送<br>检测到 2 个可见终端，无法确定具体目标<br>如需后台发送，请在目标终端中以 -lock 参数运行本程序 |
| 用 -lock 锁定 | 成功 | 已锁定终端 | 目标：…<br>方式：后台发送，不切换窗口<br>按 Alt+/ 解除锁定 |
| 解除锁定 | 信息 | 已解除锁定 | 消息将输入到当前光标位置 |
| 没有锁定时按 Alt+/ | 信息 | 未锁定任何目标 | 消息将输入到当前光标位置 |
| 目标已关闭 | 警告 | 消息未发送 | 锁定的目标已关闭，消息已丢弃<br>按 Alt+/ 解除锁定，或在新目标中按 Alt+. 重新锁定 |
| 桌面、任务栏、本程序窗口 | 警告 | 无法锁定此窗口 | 桌面、任务栏和本程序窗口不支持锁定 |
| 本程序所在终端 | 警告 | 无法锁定此终端 | 本程序所在的终端不支持锁定<br>请切换至其他窗口或终端标签 |
| 没有前台窗口 | 警告 | 未检测到活动窗口 | 请先激活目标窗口，再按 Alt+. |
| -lock 失败 | 错误 | 终端锁定失败 | 无法后台写入此终端：（原因） |

终端名优先显示光标所在行（通常是带目录的提示符），方便认出是哪个标签。

### 7.5 响应速度

按下 Alt+. 到卡片出现在屏幕上，实测（Alt+/ 解除锁定不需要识别目标，更快）：

| 前台窗口 | 耗时 | 主要花在 |
|---|---|---|
| Chrome 等普通窗口 | 32 毫秒 | 枚举进程、渲染卡片 |
| Windows Terminal（多个标签） | 45 毫秒 | 查询控制台、标题探测 |
| IDE 编辑器（没有显示终端） | 约 260 毫秒 | 尺寸探测要等完三级（共 220 毫秒）才能确认没有终端 |
| IDE 终端窗口 | 约 80～120 毫秒 | 尺寸探测（终端 10～60 毫秒后有反应） |

做过的优化：锁定和解除分成两个快捷键，不需要等待判断是否连按；识别目标移出 UI 线程；辅助进程常驻复用（每次省约 45 毫秒）；
标题探测改为同时进行（Windows Terminal 两个标签时从 0.75 秒降到约 30 毫秒）；普通窗口不启动控制台查询；
尺寸探测轮询间隔从 30 毫秒缩短到 10 毫秒，并改为逐级加大上移距离（终端单独成窗口时第 1 级就能确认）；启动时预先渲染一张卡片，
避免第一次按快捷键时加载字体的约 30 毫秒。

本程序启动后第一次查询终端时要启动辅助进程，约 40 毫秒；之后都复用。

## 8. 已知限制

- **IDE 窗口里终端和编辑器同时显示**：在编辑器里按 Alt+.，尺寸探测会发现那个正在显示的终端，于是锁定终端（后台写入），
  而不是编辑器。想发到编辑器，先把终端面板隐藏再按 Alt+.。
- **IDE 里同时显示多个终端**（分屏）：分不清是哪一个，按普通窗口处理；可在目标终端里运行 `-lock`。
- **用鼠标切换 IDE 终端标签不需要额外操作**：尺寸探测看的是“正在显示”，与有没有在里面打过字无关。
- **管理员终端**：以管理员身份运行的终端无法后台写入（`AttachConsole` 被拒），除非本程序也以管理员身份运行。
  切前台方式同样受 UIPI 限制。
- **键盘布局**：热键绑定的是 `VK_OEM_2` 物理键，换成非美式布局时可能不是 `/` 键。
- **热键冲突**：Alt+. 被其他程序占用时，锁定功能不可用，启动时打印警告，消息始终输入到当前光标；
  只有 Alt+/ 被占用时，可在已锁定的目标里按 Alt+. 解除。
- **IDE 终端停靠在主窗口里时**：底边逐级上移到 120 像素，即使终端面板只分到一部分高度，通常也能多于一行，
  因此能识别出来。这种情况目前没有实测；如果仍被判为“没有终端在显示”，可改用 Window 模式，
  或在目标终端里以 -lock 参数运行本程序。
- **热键会拦截目标程序里的同名快捷键**：注册为全局热键后，Alt+. 和 Alt+/ 不再传给前台程序。
  例如 PowerShell（PSReadLine）和 bash 里 Alt+. 原本是“插入上一条命令的最后一个参数”，本程序运行期间这个功能不可用。
- **终端里正在运行其他程序**：后台写入的内容会进入那个程序（例如 python、vim），与亲手打字效果相同。
- **Windows Terminal 关闭了应用标题**（`suppressApplicationTitle`）：标题探测无效，会退回到尺寸探测；尺寸探测也确定不了时按普通窗口处理。
